# 网页设备配对与逐台退出

日期：2026-10-27。接续 [家长控制](parental-controls-2026-10-27.md)，本阶段完成网页扫码授权、独立登录会话和逐台退出。当前为本地代码与自动验证，尚未提交或发布。

## 使用方式

1. 新设备打开家庭影视地址，在登录页选择“用已登录设备授权”，填写一个容易辨认的设备名称并生成配对码。
2. 用已登录的手机扫描二维码；也可在手机的“我的 → 登录设备 → 授权新设备”输入配对码。扫码会自动读取设备信息，**仍需本人核对账号、设备名称和配对码，点击确认**。
3. 新设备自动登录确认时使用的那个账号。手机未登录时先登录，配对码会保留；需要首次改密的账号先完成改密，再回到确认页。
4. 在“我的 → 登录设备”查看登录记录。退出指定设备需要确认；其他设备继续使用。选择“退出全部设备”会连当前设备和旧凭据一起退出。

只能授权当前账号，不能在请求中指定其他家庭成员。管理员授权时会明确提示新设备获得管理员权限；给儿童使用应先登录对应儿童账号。新设备继续使用该账号的内容分级、观看额度和连播规则，不会获得新的每日额度。

## 授权规则

| 项目 | 当前行为 |
| --- | --- |
| 有效期 | 配对请求五分钟有效，使用后失效；可取消、过期后重新生成 |
| 确认码 | 使用安全随机数生成八位易辨认字符，分成两组；二维码只包含同一家庭地址和确认码 |
| 领取凭据 | 请求设备另持有 256 位随机秘密，保存在页面内存，通过 POST 请求体发送；单凭确认码或请求编号无法领取登录凭据 |
| 数据库存储 | 只保存确认码与请求秘密的摘要；不保存原文密码、配对秘密或签发后的 JWT |
| 明确同意 | 扫码和查看设备不会自动授权，必须确认；一旦确认，不能被另一个账号覆盖 |
| 一次性领取 | 领取标记、新设备会话、登录记录与签发在同一事务中处理，并发领取只能成功一次。响应丢失后需要重新配对，不提供可反复取回令牌的接口 |
| 账号变化 | 确认后改密、禁用、修改权限或退出全部设备会使待领取授权失效；确认设备本身被逐台退出后，其尚未领取的配对也失效 |
| 请求边界 | 发起每 IP 每分钟 10 次；查看、确认各 10 次；领取/取消各 90 次；最多保留 500 个有效待处理请求。过期请求保留一天后随新请求清理 |
| 二维码 | 使用本地 `qrcode-generator@2.0.4`（MIT），不调用外部二维码服务，不向第三方发送家庭地址或授权信息 |

服务器只从已验证的登录身份确定账号和权限，请求体中的 `user_id`、角色等字段不能改变授权对象。需要改初始密码的账号不能通过配对绕过改密。

## 设备会话与撤权

每次新的密码登录、注册或配对领取都生成独立会话标识，写入 JWT 的 `sid`。刷新保留原会话标识，不能靠刷新生成替代会话逃过撤权。访问令牌仍为最长七天，会话最长三十天，刷新不会延长会话的绝对有效期；到期后重新登录或配对。

设备列表仅返回当前账号仍有效的会话，标记“此设备”，最近使用时间最多约五分钟更新一次。名称用于辨认，不能作为硬件身份的证明；同一浏览器重新登录也可能产生独立记录。较早的过期会话在新密码登录时按九十天保留窗口清理。

主 API、刷新接口、图片/媒体请求、Emby 两种路径前缀及 WebSocket 均接入设备状态验证。网页在活跃时每三十秒及窗口获得焦点时检查会话；业务请求会即时检查。已有主 WebSocket 在发送事件前重新验证；Emby WebSocket 在消息和保活时重新验证。数据库暂时无法确认设备时拒绝请求并返回暂不可用，不把这种故障直接当作设备已撤销。

修改密码、账号权限等原有账号级吊销规则继续有效。普通“退出登录”会撤销当前新式设备会话；离线时仍能清除本机登录，并提示通过设备管理撤销其他登录。

**旧版未包含 `sid` 的凭据无法逐台区分。** 保留其原有账号级校验；重新登录会创建新的设备记录，但不会让已复制的旧凭据自动失效。需要撤销旧凭据时使用“退出全部设备”。客户端会显示此边界，不将旧会话伪装成可逐台管理。

不能召回已经发出的流响应、缓存字节或下载文件，也不能强制停止修改过的第三方播放器。这里的设备管理属于登录会话管理，不是硬件绑定或 DRM。

## 接口

| 接口 | 用途 |
| --- | --- |
| `POST /api/auth/device-pairing` | 新设备发起请求，返回确认码与仅请求设备持有的秘密 |
| `POST /api/auth/device-pairing/status` | 携带请求编号与秘密轮询；批准后一次性领取登录凭据 |
| `POST /api/auth/device-pairing/cancel` | 携带请求编号与秘密取消自己的请求 |
| `POST /api/users/me/device-pairing/inspect` | 已登录设备查看待确认设备 |
| `POST /api/users/me/device-pairing/approve` | 明确确认当前账号授权 |
| `GET /api/users/me/devices` | 查看自己的有效登录会话与当前标识 |
| `DELETE /api/users/me/devices/:deviceId` | 撤销自己的指定会话，不能撤销其他账号的会话 |
| `POST /api/users/me/devices/revoke-all` | 退出全部设备并吊销旧版凭据 |
| `GET /api/users/me/device-status` | 检查当前会话 |
| `POST /api/auth/logout` | 撤销当前新式会话 |

配对响应使用 `private, no-store`。确认码位于二维码链接的 URL fragment；请求秘密与登录令牌均不进入二维码。管理操作及成功配对写入审计，领取写入正常登录记录。

同时收紧刷新令牌校验：只容忍有效签名凭据的过期时间，不会因为“同时过期”而忽略签名错误或尚未生效的声明；只接受服务器实际签发的 HS256 算法。

## 验证结果

- 相关八组 Go 包通过：model、repository、service、middleware、handler、Emby、server-lite、server。
- 新测试覆盖独立登录、刷新保留标识、单设备/全部吊销、跨账号隔离、并发一次性领取、秘密摘要存储、取消/过期、账号状态变化、确认设备撤销，以及儿童分级身份和用量不被重置。
- HTTP 验证覆盖匿名不能确认、伪造请求体不能改角色或账号、撤销后媒体/刷新请求拒绝、现有 WebSocket 停止投递，及 Emby 查询令牌、图片和流路径不能绕过撤权。
- 中间件测试覆盖缺少设备校验器时拒绝新式凭据、合法过期令牌可刷新、撤销后禁止刷新、错误签名同时过期仍拒绝、未来 `nbf` 拒绝、算法限定及设备存储故障返回暂不可用。
- 上述新链路经 race detector 验证通过。
- Chromium 完整浏览器回归 **32 组通过**；设备专项 **5 组通过**（与完整回归重叠），涵盖双设备确认、二维码显示、过期重生成、取消、退出失败恢复、单设备退出、全部退出、焦点时撤权检测及登录后返回确认。
- 前端 TypeScript/Vite 构建及既有 10 项前端逻辑测试通过。仓库既有 ESLint 9 配置缺失和 report-only UI 审计状态保持不变。

## 当前边界

本阶段接入网页界面和服务端。新设备仍需先打开能访问的家庭地址；扫码可免去在新设备输入账号密码，不能代替首次服务器发现或网络连接。Android 原生配对界面、电视遥控器、共用成员头像/家长 PIN、原生偏好同步及真实相机扫码验收仍待后续。新登录的 Emby 凭据已接入撤权验证，但不代表各第三方客户端已完成真机验收；儿童 Emby 登录继续禁用。
