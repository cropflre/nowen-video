# 管理型 Agent：影片候选匹配与人工确认

分支：`codex/family-viewing-platform`。接续逐片文字资料补全，补上未关联 TMDb 电影的入口，没有直接复用覆盖式匹配/刮削。

## 当前交付与使用

管理员说“匹配影片”，从最多六部未关联的电影中点击“查找影片候选”。也可先正常按片名找片，再说“匹配第二部”；在电影详情或当前播放页可说“匹配这部”。“补全资料”在没有可直接补全的已关联电影时会引导匹配未关联电影；“补全第二部资料”遇到未关联电影也会先进入候选匹配。

1. 按本地片名与年份搜索，展示最多六个 TMDb 候选的片名、原名、年份、简介和可打开的来源链接。仅说明片名/年份一致或差异，不输出虚构置信度，不默认选中。
2. 搜索条件可展开修改；留空年份表示不限年份。无结果时可以改片名重搜或取消，不会改用其他影片自动匹配。
3. 点击“选择此候选”只更新任务预览。核对本地影片 → 来源影片后，再点击“确认匹配此影片”，只保存 TMDb 关联。
4. 已完成回执提供“预览资料补全”，继续原有逐字段预览与独立确认流程。关联不会自动覆盖片名、已有文字、图片、评分或儿童分级，也不改动原文件/NFO。
5. 可先“撤销本次补全”，再“撤销本次匹配”。有后续资料或身份变化时整体拒绝撤销匹配，避免资料留下而来源丢失。

目前仅支持电影库/其他类型库中，尚未关联 TMDb 的 movie 媒体；已有 TMDb 关联直接走资料补全，重匹配使用原有资料页面。剧集、其他资料源、成人来源、批量匹配及文件整理不在本轮。TMDb 搜索明确关闭成人结果，不承诺所有现有电影都能在该来源找到。

## 服务端契约

- 不新增模型工具，不向 AI 发送库目录、文件路径、观看记录或候选。候选搜索仅把管理员确认的搜索词/默认片名及年份发送给配置的 TMDb 资料源。
- 使用 Full/Lite 既有 `agent_runs`，任务类型 `match_movie`。服务端保存搜索条件、候选集合、当前选择和完整审批快照；客户端不能提交任意 TMDb ID 直接写库。
- `POST /api/admin/agent/runs/matches` 搜索并创建草案；`POST /api/admin/agent/runs/:runID/select` 从本次候选中选择；确认/取消/撤销复用原任务接口。本人管理员才能读取与操作，普通成员、儿童、禁用、强制改密或已撤销权限的账号被拒绝。
- 搜索读取八秒截止、响应上限 1 MiB、第一页最多检查二十个结果；过滤无效/重复 ID 和异常长标题，简介截断展示。跨主机/协议重定向不继续携带凭据，资料源异常不回显密钥或内部 URL。
- 选择候选会轮换审批摘要；旧摘要不能选择或确认，不延长十分钟期限。绑定发起人、权限版本、本地影片身份/年份/字段/NULL/更新时间、库配置、搜索条件、候选、选择及有效期。
- 成功重新搜索会在同一事务中取消本人同片旧草案；失败不修改影片。取消、过期、资料或库设置变化的草案不能产生新关联。搜索返回前再次检查权限和快照，拒绝过时的来源结果。
- 确认在数据库事务中重新检查状态和快照，再按预期身份/版本写入唯一关联并保存回执；不重复访问资料源，不触发刮削回调。八次并发确认只发生一次实际身份变化。
- 撤销只在关联仍为本次选择、片名/年份和原四个文字字段及 NULL 状态未变化时恢复原关联。支持原关联为 NULL 或零；先撤销后续补全后可再撤销匹配，重复确认/撤销返回已有回执。
- 本轮给资料审批快照增加年份与关联 NULL 信息。此前尚未确认的旧版资料草案需重新预览，已完成回执保留；本机升级前真实库没有此类草案。

## 网页反馈与布局

候选优先展示，修改搜索词/年份默认收起；搜索条件有未提交修改时禁止选择和确认。匹配草案展开时给任务区更多高度，聊天区让出空间，320px 下输入框保持可见。选择期间按钮互斥；切换账号后不会应用迟到结果。

操作错误与任务列表读取错误分开保存。三秒轮询成功不会抹掉“有后续资料不能撤销”等操作错误，下一次成功操作再清除。

## 验证

- 相关八个 Go 包通过；`TestAgentMovieMatch`、原资料补全/扫描服务与 HTTP 用例通过 race 检查。
- SQLite/HTTP 覆盖无默认选择、搜索/选择无影片写入、候选集合防伪、选择后旧摘要失效、期限不延长、八次并发确认仅一次真实更新、用户隔离、权限变化、库/影片变化、搜索中数据变化、来源失败、重搜取消旧草案、无候选不能确认、NULL 恢复及资料补全/匹配的撤销顺序。
- 实际后端 + Chromium 十组通过，没有模拟应用 API；候选/详情来自隔离 HTTP 资料源。覆盖聊天指代、同名不同年份、320px、修改条件禁止旧确认、显式确认、回执刷新、资料补全联动、错误在轮询后保留、撤销保护、空结果、来源失败、重新搜索、陈旧身份、源文件/NFO 字节和儿童分级保留。
- 实际隔离后端重启后，已选择但未确认的草案仍在，选择、摘要及期限不变；确认与重复确认不再读取来源，撤销成功。最终记录包含八条持久化回执。
- 原有 38 组浏览器回归、10 个前端逻辑用例及 TypeScript/Vite 构建通过。UI audit 为原有 report-only，不将其表述为 lint 通过。

### 真实 TMDb

用公开影片“流浪地球（2019）”探测当前配置的真实 TMDb，搜索得到候选，详情读取成功。进一步在隔离数据库中创建该公开影片夹具，完成真实来源搜索 → 选择 → 确认关联 → 预览并确认补全四个字段 → 验证依赖保护 → 依次撤销。关联、空缺字段和夹具原文件恢复，完整链路通过。

该测试没有发送真实 NAS 库中的片名，也未对原库保存匹配或补全。它证明真实来源与隔离业务链路可用，不代表原库每部影片均已被人工核对。

报告、截图和私有夹具位于忽略跟踪且权限受限的 `data/agent-match-acceptance-2026-10-28/`。脚本 `web/scripts/agent-movie-match.browser.cjs` 要求显式隔离 manifest，拒绝非 loopback、原 28888/28889 端口及隔离目录之外的数据库。

## 本机服务更新与数据保留

检查时原 28888 后端已停止，28889 网页服务仍在。已为原数据库创建一致性备份并保留上阶段程序，再启动新后端，保留原网页服务；后台独立进程信息保存在忽略跟踪的升级目录。

原账号短期兼容会话通过，网页代理返回的新“补全资料”响应包含六部待匹配候选，任务接口正常，前端与 API 健康均为 200。原有一个账号、两个库、100 部电影、八条观看记录，以及收藏、分级、权限和任务表的既有字段逐项摘要一致。

真实库仍有零条 Agent 任务、零个 TMDb 关联，没有代用户搜索真实片名、创建真实预览、确认匹配或执行补全。备份和核对结果位于 `data/agent-match-local-upgrade-2026-10-28/`。

本轮尚未提交代码、推送、合并 main 或发布制品。真实原库的每次关联仍需管理员逐片选择和确认；自动批量匹配、重新匹配已有资料、剧集与其他来源留待后续。
